# ECG 캡스톤 — 4번 담당 실행·평가 검증 결과

작성일: 2026-11-06  
자료 성격: **발표 담당자 전달용 검증 결과**. 기존 팀원 결과의 독립 확인 범위와 미검증 범위를 구분함.

## 1. 검증 목적
1번 라벨·데이터 분할, 2번 ECG 재구성, 3번 질환 분류의 실행 조건 및 결과를 교차 검토한다. 기존 v1 결과와 v2 라벨 제안을 혼합하지 않는다. 기존 결과 파일은 수정하지 않는다.

## 2. 라벨·데이터 분할 검산(1번)
- 전체 ECG 998개 중 분류 대상 990개, 제외 8개.
- 분류용 split: train 796 / validation 96 / test 98.
- v1 `source_NORM` 545개 → v2 `target_v2_NORM` 529개. **정상·질환 동시 표시 16건의 정상 라벨이 해제**됨. 다른 네 질환의 양성 개수는 변하지 않음.
- 추가 검토 표시 36건; 환자 단위 split 중복 0건(제공 CSV 기준).
- **주의:** v2 CSV의 `NORM` 열도 수정 후 값이므로, v1과 비교할 때 `source_NORM` 열을 사용해야 함. 8개 분류 제외 ECG를 정상 음성으로 처리하면 안 됨.
- v2 라벨 정책은 제안 단계이므로 기존 v1 체크포인트의 성능을 v2 평가 결과라고 주장할 수 없음.

근거: `ecg_classification_v2/preserved/labels_v2/tables/ecg_labels_v2_classifier_998.csv`, 별첨 `role4_label_changes_16.csv`.

## 3. ECG 재구성 재실행(2번)
- 제공 `best_model(1).pth` SHA-256: `e6cfd066ab8c88f1e37d5635beff7df2c3606509d0e1455392dab6642d8c6a64` (팀 문서와 일치).
- 모델: `model_dilated.ECGDilatedModel`, 체크포인트 epoch 28. CPU/PyTorch 2.10.0+cpu로 재실행.
- 입력: 100Hz, 10초/1000샘플, mV, Lead I. 출력: float32 `(1000,12)`.
- ECG 9번과 65번에서 저장된 C 입력의 재구성 파형과 직접 비교한 결과, **각각 최대 절댓값 차이 2.38418579×10⁻⁷ mV**로 수치 일치. 입력 Lead I은 완전히 보존됨.
- `evaluate.py` 오차 계산은 코드상 관측 Lead I을 제외한 11개 예측 유도만 대상으로 함. 다만 전체 테스트 세트의 MAE 재현까지 수행한 것은 아님.

근거: 제공 `predict_ecg.py`, `best_model(1).pth`, `role3_classification_20261101_final(1).zip` 내 `examples/inputs/`, `ecg_reconstruction/evaluate.py`.

## 4. 질환 분류 재실행(3번)
- `role3_classification_20261101_final(1).zip`의 **v1 seed 42 모델**을 CPU에서 다시 로드하여 저장된 예제와 비교.
- 검사 대상: ECG 9번·65번 × 입력 A(Lead I), B(실측 12유도), C(Lead I+추정 11유도) × 다중라벨·이진분류 = **총 12건**.
- **12/12건 모델 로드·추론 성공, 12/12건 최종 판정 일치**.
- 저장된 확률과 재실행 확률의 최대 절댓값 차이: **1.1920928955×10⁻⁷** (확률 단위). 이는 부동소수점 계산 차이 수준.
- `label_policy_status` 설명 문자열은 저장된 JSON과 다름. 또한 저장된 JSON에는 `input_file_sha256` 필드가 있고, 이번 직접 API 호출 결과에는 해당 필드가 없음. **수치·판정은 일치하나 JSON 전체가 동일한 것은 아님.** 후자는 CLI 출력 시 추가되는 항목으로, 모델 예측 불일치를 의미하지 않음.
- 정규화 평균/표준편차, 저장 임계값, checkpoint/threshold SHA-256 검사를 실제 로드 과정에서 통과함.

근거: `classifier_inference.py`, `models/{multilabel,binary}/{A,B,C}/seed_42/`, `examples/inputs/`, `examples/outputs/`. 별첨 `verification_results.csv`.

## 6. 발표 슬라이드에 넣을 핵심 문장
> 4번 담당에서는 데이터 라벨·분할 및 모델 입출력 규격을 교차 점검하고, 제공된 체크포인트로 재추론하여 저장 결과와 비교하였다. 라벨 v2 변경 16건을 독립 확인했으며, ECG 2건의 재구성 파형은 최대 2.38×10⁻⁷ mV 차이로 저장된 C 입력과 일치했다. 분류 모델은 A·B·C 입력 및 두 분류 과제의 총 12건 모두에서 최종 판정이 일치했다. 다만 과거 통합 코드의 출력 대조와 전체 테스트 성능 재현은 아직 수행하지 않았다.

## 7. 발표 전 권장 조치
1. `integration` 폴더와 이전 4개 ECG 결과가 있으면 원본을 확보해 개별 프로그램 출력과 직접 비교.
2. 팀에서 채택한 라벨 정책(v1 또는 v2)을 명시하고, v2 채택 시 해당 모델의 재학습·평가 여부 확인.
3. 전체 테스트 성능을 '4번 담당이 재현했다'고 말하지 않도록 발표 문구 확인.
